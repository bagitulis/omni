ISSUE #1: Repository Methods Lack Tenant Filters
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Severity: MEDIUM (Mitigated by schema isolation)
Affected Files (3):
  1. backend/internal/repositories/shopee_order_repository.go
     - FindAll() method (line 37-61)
     - FindByOrderSN() method (line 54-61)
  
  2. backend/internal/repositories/lazada_order_repository.go
     - Same methods without tenant_id filtering
  
  3. backend/internal/repositories/tiktok_order_repository.go
     - Same methods without tenant_id filtering

Problem Example:
  ❌ BEFORE (no tenant filter):
     repo.FindByOrderSN(orderSN)
     → SELECT * FROM shopee_orders WHERE order_sn = ?
     → Could match orders from ANY tenant (if schema wasn't enforced)

Current Risk Assessment:
  Database Level: 🟢 LOW - PostgreSQL schema isolation prevents access
  Application Level: 🟡 MEDIUM - No explicit tenant validation
  Overall Risk: 🟢 LOW - Multiple layers prevent breach

Why It's Not Critical:
  - Handler retrieves GetTenantDB(tenantID) which sets search_path
  - All queries execute ONLY in that tenant's schema
  - PostgreSQL enforces this at driver level
  - Cannot be bypassed by SQL injection

Recommendation:
  Add tenantID parameter to these methods for defense-in-depth
  Effort: 2-3 hours
  Impact: Eliminates entire class of potential bugs

FIX EXAMPLE:
  ✅ AFTER (with tenant filter):
     repo.FindByOrderSN(tenantID, orderSN)
     → SELECT * FROM shopee_orders WHERE tenant_id = ? AND order_sn = ?
     → Explicit validation at application level

File: backend/internal/repositories/oauth_repository.go
Method: FindStateByState() (line 42-51)

Problem:
  FindStateByState(state) → WHERE state = ?
  Doesn't validate which tenant the state belongs to

Recommendation:

  Include tenant validation in callback handling
  Effort: 1 hour
