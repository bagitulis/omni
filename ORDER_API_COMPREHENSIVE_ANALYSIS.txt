1.1 SHOPEE ORDERS
-----------------

Available Order Actions:
  GET  /api/shopee/orders              - List orders (paginated)
  GET  /api/shopee/orders/:orderSn     - Get order details
  POST /api/shopee/orders/ship         - Ship an order
  POST /api/shopee/orders/cancel       - Cancel an order

Order Data Fields:
  Core: order_sn, order_status, total_amount, currency, buyer_username, shop_id
  Items: item_id, model_id, item_name, model_name, item_sku, model_sku, quantity, price
  Timestamps: created_at, updated_at, order_timestamp

Request Structures:
  ShipOrder: { order_sn, tracking_number? }
  CancelOrder: { order_sn, cancel_reason }

SDK Methods (backend/pkg/shopee/order_api.go):
  GetOrderList(timeFrom, timeTo, timeRangeField, orderStatus, cursor)
  GetOrderDetail(orderSNList)  // Max 50 orders per request
  ShipOrder(ShipOrderRequest)
  CancelOrder(CancelOrderRequest)

Order Statuses: UNPAID, UNSHIPPED, SHIPPED, COMPLETED, CANCELLED, RETURN_REFUND

Limitations & Constraints:
  - Batch limit: 50 order SNs per GetOrderDetail request
  - Time range: 15 days maximum window
  - Pagination: Cursor-based with next_cursor field
  - Order-level operations (not item-level like Lazada)

  - Structured reason codes for cancellation

2. UNIFIED ORDER SYNC SERVICE
================================================================================

Service Architecture:
  OrderSyncOperations (backend/internal/services/sync/order_operations.go)
  ├── SyncByCategory(category, days, platforms)
  ├── SyncPlatformOrders(platform, category, days)
  └── fetchOrderItems(platform, orders)
      └── Platform-specific OrderManager implementations
          ├── ShopeeOrderManager
          ├── LazadaOrderManager
          └── TiktokOrderManager

Order Status Mapping (Cross-platform):
  Frontend Category → Shopee Status → Lazada Status → TikTok Status
  ─────────────────────────────────────────────────────────────────
  unpaid           → UNPAID        → PENDING        → UNPAID
  unprocess        → UNSHIPPED     → READY_TO_SHIP  → UNSHIPPED
  processed        → SHIPPED       → SHIPPED        → SHIPPED

Unified Order Data Structure (type Order):
  id, order_sn, order_no (frontend display), platform, status, category
  total_amount, currency, buyer_username
  tracking_number, shipping_carrier
  sku, product_name, variation_name, quantity (FLATTENED for frontend)
  items (optional nested array for backward compatibility)
  created_at, updated_at

Sync Workflow:
  1. Frontend POST /api/orders/sync/{category}
  2. Backend fetches from platform APIs (date range: -7 days default)
  3. Batch process order items (max 50 per batch for safety)
  4. Clear old orders with same status from database
  5. Insert/update fresh data in database
  6. Return summary { platform: { success, count, error } }
  7. Frontend then GET /api/orders/{category} to retrieve from DB

Batching Details:
  Platform Limits:
    - Shopee: 50 order SNs per GetOrderDetail request
    - Lazada: Item-based, safe for batching
    - TikTok: Page token-based pagination
  Implementation: Split into 50-item chunks, fetch separately, merge before save
